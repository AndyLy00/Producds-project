# Корзина — Smart Shopping

Мобильное PWA-приложение для списков покупок. Основной экран списка следует первому выбранному визуальному направлению: тёплый бумажный фон, тёмно-зелёные элементы и томатные акценты.

## Готово в первой версии

- Несколько списков и создание новых списков.
- Добавление продуктов быстрым вводом или через подробную форму.
- Количество, единицы измерения, категория и заметка.
- Автоматический выбор категории по названию и сортировка продуктов по категориям.
- Отметка покупки, возврат в список и очистка купленных продуктов.
- Редактирование и удаление продуктов.
- Избранные продукты с быстрым повторным добавлением.
- История завершённых списков и повтор покупки.
- Поиск в открытом списке.
- Светлая и тёмная темы.
- Хранение через IndexedDB с резервным сохранением в localStorage.
- Аккаунт (почта и пароль или Google): списки сохраняются в MongoDB, синхронизируются между устройствами и могут вестись вместе.
- PWA-манифест и кеширование для повторного открытия без сети.

При первом запуске отображаются демонстрационные списки. Все последующие изменения сохраняются на устройстве.


## Android-приложение

Тот же интерфейс упакован в Android-приложение через [Capacitor](https://capacitorjs.com/). Проект Android Studio лежит в `android/`.

Нужны JDK 21 (полный, с `jlink`) и Android SDK с платформой 36; путь к ним задаётся переменными `JAVA_HOME` и `ANDROID_HOME`.

```bash
npm ci
npm run apk          # веб-сборка + cap sync + gradlew assembleDebug
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка; для публикации в Google Play нужна подписанная release-сборка.

Как это устроено:

- `vite.android.config.ts` собирает отдельный бандл в `dist/android` с точкой входа `src/native/main.tsx` — без рамки телефона и нарисованной клавиатуры, которые нужны только прототипу в браузере.
- `src/native/index.tsx` реализует ту часть API `src/mobile`, которой пользуется приложение (`MobileScroll`, `BottomSheet`, `KeyboardInput`, `useKeyboard`, `useKeyboardInsets`), поверх настоящих прокрутки и клавиатуры. При Android-сборке импорт `./mobile` подменяется на этот модуль.
- Системная кнопка «Назад» закрывает форму, затем возвращает к спискам и только потом закрывает приложение.
- Иконки и заставка сгенерированы из `assets/logo.png` командой `npx @capacitor/assets generate --android`.

### Сборка на GitHub и обновления

После каждого изменения в ветке `main` сценарий `.github/workflows/android.yml` собирает подписанный APK и публикует его в разделе Releases с тегом `build-<номер сборки>`. Номер сборки становится `versionCode` приложения, а версия получает вид `1.0.<номер>`.

При запуске и при возврате в приложение (не чаще раза в полчаса) оно запрашивает последний релиз репозитория. Если его номер больше собственного, сверху появляется плашка «Доступно обновление»: кнопка «Обновить» открывает загрузку APK в браузере, крестик скрывает плашку до следующей версии. Логика лежит в `src/native/update.tsx`. В локальной сборке (`npm run apk`) номер равен 0, и проверка отключена.

Все сборки подписываются одним ключом — иначе Android не установит новую версию поверх старой. Ключ хранится в секретах репозитория `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` и `ANDROID_KEY_ALIAS`; в сам репозиторий он не входит.

## Сайт, аккаунт и хранение в MongoDB

Сайт и серверная часть размещаются на Vercel (корневая папка проекта там — `smart-shopping`, настройки в `vercel.json`). Сайт — это та же сборка без рамки телефона, что и в Android-приложении: `npm run build:web` кладёт её в `dist/web`.

Серверная часть — функции в `api/`:

- `api/auth.js` — аккаунт: регистрация и вход по почте и паролю, подтверждение почты кодом, сброс забытого пароля кодом из письма, смена пароля (другие устройства выходят), удаление аккаунта, вход через Google. Пароли хранятся только в виде хеша (scrypt). От перебора защищает счётчик попыток: после 5 неверных паролей вход в аккаунт закрывается до конца 15-минутного окна, с одного адреса — не больше 30 неудачных входов за 15 минут и 10 регистраций в час.
- `api/sync.js` — синхронизация. Каждый список хранится отдельным документом и может принадлежать нескольким аккаунтам; профиль (магазины, шаблоны, рецепты, свои категории, тема) — один документ на аккаунт.
- `api/share.js` — совместные списки: ссылка-приглашение на 7 дней (или письмо), вступление, выход, участники.

Правки сливаются, а не перезаписываются (`shared/merge.js`, общий для приложения и сервера): у каждого списка, продукта, рецепта и т. д. есть время последнего изменения, удаление оставляет «надгробие», и при встрече двух копий для каждого объекта побеждает изменённая позже. Поэтому правки разных продуктов с двух устройств или от двух людей сохраняются обе. Пока приложение открыто, оно спрашивает сервер об изменениях каждые 5 секунд; без сети работает с копией на устройстве и досылает изменения позже.

Переменные окружения функций:

| Переменная | Зачем |
| --- | --- |
| `MONGODB_URI` | строка подключения к MongoDB (имя базы по умолчанию `korzina`, меняет `MONGODB_DB`) |
| `AUTH_SECRET` | случайная строка для подписи сессий и кодов |
| `RESEND_API_KEY`, `EMAIL_FROM` | отправка писем через [Resend](https://resend.com): коды подтверждения и сброса пароля, приглашения. Без них эти функции скрыты |
| `GOOGLE_CLIENT_ID` | идентификатор OAuth-клиента Google (тип «Web application», источник — адрес сайта). Без него кнопка Google скрыта |
| `APP_ORIGIN` | адрес сайта для ссылок в письмах, если он отличается от адреса запроса |

Вход через Google в Android-приложении идёт через браузер (Google не разрешает вход внутри WebView): приложение открывает `/?app-login=…` (`src/native/app-login.tsx`), а после входа браузер возвращает в приложение одноразовый код по ссылке `korzina://auth`, который обменивается на сессию только вместе с секретом, оставшимся на устройстве.

Тесты серверной части и слияния: `MONGODB_URI=<временная база> npm run test:api` (без переменной тесты сервера пропускаются).

## Возможности приложения

- **Списки:** меню «⋯» на карточке и в списке — переименовать, вести вместе, отправить текстом в мессенджер, напоминание, магазин, сохранить как шаблон, завершить, удалить. Удаление продуктов, списков и очистку купленного можно отменить в течение 5 секунд.
- **Порядок:** «По категориям» (или в порядке отделов выбранного магазина) либо «Свой порядок» с перетаскиванием за ручку. Свои категории и магазины — в «Настройках».
- **Подсказки** при вводе продукта — из ранее купленного, шаблонов и рецептов.
- **Шаблоны** создаются из списка и предлагаются при создании нового.
- **Рецепты** — вкладка «Рецепты»; ингредиенты добавляются в выбранный список.
- **Напоминания** — уведомление в выбранное время (в Android — системное, на сайте — пока вкладка открыта).
- **Виджет** Android показывает, что осталось купить в первом списке (`ListWidgetProvider.java`).

## Устройство данных

Типы и операции над данными — `src/model.ts`, хранение на устройстве (IndexedDB с копией в localStorage) — `src/shopping-data.ts`, обмен с аккаунтом — `src/cloud-sync.ts`. Данные прежних версий приложения переводятся в новый формат при загрузке.
